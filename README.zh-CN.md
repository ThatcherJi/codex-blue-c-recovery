# Codex 蓝色 C 修复工具

针对 Windows Codex 桌面端“旧对话发送按钮变灰，后台还在工作”的本地恢复方案。它包含自动补齐丢失回复和蓝色 C 托盘按钮，可继续使用原来的对话界面。

## 安装

需要 Windows 11 x64、Microsoft Store 版 Codex、Node.js 24 及以上，以及 Windows 自带的 .NET Framework 4.x 编译器。无需管理员权限，无需安装 npm 依赖。

1. 点击仓库的 **Code → Download ZIP**，解压到长期保留的可写目录，例如 D 盘。
2. 查看脚本后，双击 **Install.cmd**。它会编译托盘程序、创建桌面快捷方式并启动蓝色 C。
3. 右键蓝色 C，看到“自动保护：已启用”即可。不要同时运行两份保护工具。

默认不增加登录自启。需要时，退出已有蓝色 C 后，在解压目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -StartOnLogin
```

Node 不在 PATH 中时，可加 `-NodePath 'D:\你的目录\node.exe'`。不要删除或移动正在使用的安装目录。

## 日常使用

- 保持蓝色 C 运行：在发现新的 Codex 主进程时启用自动保护，补齐之后捕获到的丢失回复。
- 单击蓝色 C：先保存诊断，再尝试只读配置恢复；没有恢复时重开 Codex，可能中断正在执行的桌面任务。
- 右键“检查状态（不重启）”：只检查。
- 右键“自动补齐丢失回复（不重启）”：控制自动保护。自动保护本身不重启应用。
- 右键“打开最新诊断文件夹”：查看手动恢复前的记录。

退出托盘本身不会移除已装入当前 Codex 进程的保护。先取消自动保护，或执行 `Uninstall.ps1`；卸载会移除本工具对应的快捷方式和登录启动项，保留源码与日志，不停止 Codex。

## 原理与验证

原始三次实验均发现：后台生成 34 条内部回复，界面收到 21 条，13 个请求持续等待。补投原回复后，等待数降为 0。之后五次自动保护实验也都补齐 13 条，等待数和检查错误数均为 0。

自动保护只补发已经生成的原回复，不重发用户消息、不重新执行写操作。另有一次只读查询恢复，严格限于已审查过的应用实现。它不修改官方安装文件，但会通过短暂开放的本机诊断接口挂载内存补偿；完成后关闭诊断接口。

公开包沿用这套实现，并调整了路径和安装方式。已完成的同机实验不能代表所有电脑或未来版本均有效；具体检查见 [验证记录](docs/VALIDATION.md)。官方底层故障仍需应用更新解决。

所有记录留在安装目录，无遥测、无自动上传。公开分享日志前请查看内容。公开包的手动快照只保存运行元数据及工具日志，不备份聊天数据库或账号配置。
